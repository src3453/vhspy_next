# 文字多重放送 (JTES / CCIR System D) 再現計画

## 目的

日本のアナログテレビ文字多重放送（NHK・民放の「文字放送」、国際的には CCIR/ITU-R **Teletext System D**、通称 JTES）を、`vhs-core` の VBI 信号として**実際にデコード可能な形で**エンコードできるようにする。現状の NTSC 文字多重は NABTS 風の擬似乱数（`vbi.rs` の `render_teletext`）であり、中身に意味がない。

段階は次の 3 つ。

1. **ハイブリッド方式（符号化伝送方式、1985 年制定）** のデータライン・パケット・データグループ・番組データを規格どおりに生成する
2. **パターン方式**（画素で送る方式）の画面を送れるようにする（範囲は「パターン方式の扱い」を参照）
3. 受信側（スライス → 誤り訂正 → 8 単位符号の解釈 → 画面描画）と、**付加音**（MUSCOT 符号）を ymfm の **YM2413 (OPLL)** で鳴らす

本文中の「別表」「別記」は、下記の告示（郵政省告示第百二十五号）の別表番号を指す。

## 方式の全体像

### パターン方式とハイブリッド方式

- **パターン方式**（パターン伝送方式）: 画面を画素単位で順次送る（ファクシミリ型）。1981 年 3 月に電波技術審議会答申、1983 年 10 月に NHK が東京・大阪で実用化試験局として開始。漢字 ROM が不要な代わりに伝送効率が悪い。
- **ハイブリッド方式**（符号化伝送方式）: 文字は符号、図形は画素（フォトグラフィック）・モザイク・DRCS・ジオメトリック、さらに付加音を符号で送る。1985 年 10 月に省令・告示を全面改正して制定。コード伝送で同じ番組数の 5〜10 倍の効率。
- **両者は物理層とデータラインが同一**（5.727272 Mbit/s、296 ビット、同じクロックラン・フレーミングコード）。データパケットのプリフィックス中の**サービス識別符号**でパターン方式や他サービスと区別する（沢辺論文）。

### 階層構成（BT.653 Fig. 9 / 沢辺論文 図 2）

```text
番組 (Session)       番組管理データ + ページデータ（または番組索引データ）
                       └ データヘッダ (HI=01/14) + データユニット (DI=01/15) …
データグループ        SOH + データグループヘッダ + … + ETB/ETX/EOT + CRC-16
データパケット (272)  プレフィックス 14 + データブロック 176 (22 バイト) + チェック 82
データライン (296)    クロックラン 16 + フレーミングコード 8 + データパケット 272
物理層               NRZ 2 値、364 fH、ロールオフ 0.6
```

## 規格値まとめ

### 物理層（BT.653-3 Table 1b System D、山田論文 表 1）

| 項目 | 値 |
|---|---|
| ビットレート | 5.727272 Mbit/s ± 3×10⁻⁶ = **364 fH = 8/5 fsc** |
| ビット周期 Tc | 1/(364 fH) ≈ 0.1746 µs |
| 重畳位置 | 水平同期パルスの始まりから、文字信号の最初の立上りの**振幅 50 % 点まで 56 Tc**（= 9.78 µs、BT.653 の許容差 ± 0.35 µs）。データライン 296 Tc の後、次の同期まで 12 Tc（省令 別図第三号） |
| 振幅 | "1" = **70 %**（± 2.5 IRE）、"0" = **0 %**（± 2.5 IRE）。ペデスタル 0 %、白 100 % を基準 |
| 信号形式 | 2 値 NRZ |
| スペクトル整形 | 遮断周波数 fc = クロック周波数の 1/2、ロールオフ率 η = 0.6 の余弦ロールオフ。S(f)=1（f≤fL）、½(1+cos((f−fL)/(fU−fL)·π))（fL<f<fU）、0（f≥fU）。fU=(1+η)fc、fL=(1−η)fc |
| データライン長 | 296 Tc（364 Tc の 1 ラインに収まる） |
| 重畳区間 | 省令の規定は **14〜16 H、21 H、277〜279 H、284 H**（2011 年時点の第6条、改正案では第7条）。最初のフィールドの n H を使うときは、次のフィールドの (n + 263) H も併せて使う。山田 表 1 の「10〜21 H、273〜284 H」は 1985 年答申以前の物理的な範囲 |
| 位相の連続性 | 2 ライン以上に重畳する場合、各ライン・次フィールドの対応ラインとの間で CR の位相が連続し、FC の間隔は 364 Tc の整数倍。開始位置を各ライン 56 Tc に固定すれば自動的に満たされる |

既存の NABTS 実装（`vbi.rs`）との違いは開始位置（10.5 µs → 9.78 µs）とスペクトル整形（`nrz` の余弦エッジではなくロールオフ 0.6 のフィルタ）のみで、振幅 70 IRE・364 fH は同じ。

実装上の注意: ロールオフ 0.6 のナイキストパルスで描くと、クロックラン 1 ビット目の立上りはビット区間の境界で 58.6 % になり、50 % を横切るのは境界より **0.0608 Tc 早い**。`jtes::wave` は `LineFormat::start` を「50 % 点」と定義し、ビット区間の始まりをそこから `EDGE_TO_CELL_TC` だけ後ろに置く（テストで波形から 50 % 点を測って確認）。

### データライン（別表第一号）

バイト番号 B1〜B37、各バイト内のビット番号 b1〜b8 は**送出順**。2 進値は b8 が最上位なので、**バイトは LSB から送る**（既存の `bytes_lsb` と同じ）。

| 位置 | 内容 |
|---|---|
| B1〜B2 | ビット同期符号（クロックラン）`1010101010101010`（送出順） |
| B3 | バイト同期符号（フレーミングコード）`11100101`（送出順 b1→b8）。データがなくても CR・FC は送る |
| B4 b1〜b4 | サービス識別情報ビット |
| B4 b5〜b8 | サービス識別のチェックビット（(8,4) 拡大ハミング） |
| B5 b1〜b4 | 連続性指標 CI（0〜15 を巡回、送出単位内で連続） |
| B5 b5 | 伝送制御フラグ（送出単位の最初のパケットで 1） |
| B5 b6 | 誤り検出符号化区間識別フラグ（SOH または STX を含むパケットで 1） |
| B5 b7 〜 B27 b6 | **データブロック 176 ビット（22 バイト、D1〜D22）**。ラインのバイト境界と 6 ビットずれる点に注意 |
| B27 b7 〜 B37 b8 | チェック符号 82 ビット |

サービス識別符号（B4、送出順 b1〜b8）:

| 送出モード | b1..b8 | 用途 |
|---|---|---|
| 送出第1モード | `0100 1001` | 逐次受信処理 |
| 送出第2モード | `0101 0100` | 逐次受信処理 |
| 送出第3モード | `0110 0010` | 記録受信処理 |
| 送出第4モード | `0111 1111` | 記録受信処理 |
| 補助信号 | `1110 1100` | 番組索引データ |
| 運用信号 | `1111 0001` | 放送局の運用 |

**チェック符号 — (272,190) 短縮化差集合巡回符号**:

- 情報ビット 190 個（B4 b1 〜 B27 b6）を送出順に a271, a270, …, a82 とし、a271X²⁷¹+…+a82X⁸² を
  **G(X) = X⁸² + X⁷⁷ + X⁷⁶ + X⁷¹ + X⁶⁷ + X⁶⁶ + X⁵⁶ + X⁵² + X⁴⁸ + X⁴⁰ + X³⁶ + X³⁴ + X²⁴ + X²² + X¹⁸ + X¹⁰ + X⁴ + 1**
  で割った剰余 r81…r0 を B27 b7 から順に（r81 が先）置く。組織符号なので LFSR 1 本で生成できる（山田論文 図 1）。
- Weldon の (273,191) 差集合巡回符号を 1 ビット短縮したもの。多数決論理復号で 1 パケット 8 ビット以下の誤りをすべて訂正。改良アルゴリズム（市販 IC）では約 11 ビット。
- 誤り訂正・検出の機能分担（山田 表 2）: FC は 8 ビット中 1 ビット訂正、CI は連続 15 パケット以下の抜けを検出、CRC は訂正後のページデータの誤りを約 1/2¹⁶ で見逃す。

### データグループ（別表第二〜四号）

- データグループは 1 個以上の「単位」で構成。最初の単位は 1 データブロック、2 番目以降は 1 個以上のデータブロック。
- 開始符号: 先頭は **SOH (00/1)**、その他は **STX (00/2)**。終了符号: ページの最終データユニットの後は **ETX (00/3)**（最終ページ・番組索引の最後は **EOT (00/4)**）、その他は **ETB (01/7)**。
- 各単位の末尾 2 バイト（D21・D22）に **CRC-16**: G′(X) = X¹⁶ + X¹² + X⁵ + 1。区間は単位の開始符号から終了符号まで。CRC をデータブロック末尾に合わせるため、データユニット末尾に NUL を詰める（データ長には含めない）。
- データグループヘッダ（DB1〜DB7）:

| | b8 | b7〜b5 | b4〜b1 |
|---|---|---|---|
| DB1 | SOH | | |
| DB2 | データグループ識別符号（4 ビット: 番組管理・ページ = 0、番組索引 = 15） | | データグループ再送符号（0 = 再送なし、1〜15） |
| DB3 | データグループリンク符号 | データグループ連続番号（7 ビット、0〜127） | |
| DB4〜DB5 | データグループサイズ（データブロック数、DB4 が上位） | | |
| DB6〜DB7 | 運用データ | | |

### 番組データ（別表第五〜十一号）

- 番組データ = 番組管理データ + ページデータ、または番組索引データ。各データはデータヘッダ + データユニット列。
- **データヘッダ**: 情報分離符号 **01/14** + データヘッダパラメタ（番組 **02/0**、ページ **02/1**、番組索引 **02/2**、継続 **02/3**）+ データヘッダデータ長 + データ。
  - 番組データヘッダ: マガジン番号（BCD 1 桁、0 = 総目次・字幕）、番組番号（BCD 3 桁、000 = 総目次、999 = 字幕、A00〜AFF = 試験信号）、ページ総数、機能レベル（基本 = 0 / 追加 = 1）、番組形態、提示デバイス、ページ進行、更新フラグ、番組データ長。
  - ページデータヘッダ: ページ番号（BCD 2 桁）、提示デバイス、表示モード制御（多画面・スーパー・スクロール）、提示更新制御、初期提示制御（書式: 標準横書 0 / 標準縦書 1 / 高密度横書 2 / 高密度縦書 3 / 欧文横書 4）、ヘッダラスタ色・ラスタ色。
  - 具体的なバイト配置は別表第七〜十号の画像（`992650121.jpg`〜`992650151.jpg`）。
- **データユニット**: PB1 = データユニット分離符号 **01/15**、PB2 = データユニットパラメタ、PB3 b8 = リンクフラグ、PB3 b7〜b1 + PB4 = データ長（最大 4,095 バイト）、PB5〜 = データ。

- **送出方法**（別表第六号）: 1 番組は 1 本の H と次フィールドの対応 H（例: 21 H と 284 H）、1 つの送出モードを使う。非一括形番組のページ送出間隔は「直前ページの送出時間 × 3 + 1 秒」以上。番組索引は標準 20 秒、30 秒以内の間隔。1 ページ（または一括形番組全体）は最大 300 または 1,200 パケット。

### 表示（別表第十二・十三号、沢辺論文）

- **ユニットスクリーン**: 標準密度（レベル A）**248 × 204 画素**、高密度（レベル B）496 × 408 画素。座標は 1/256（高密度 1/512）単位。ヘッダ文表示領域は上端の 192〜204、本文表示領域は 0〜192。
- 文字の大きさ（標準密度横書、単位 1/256）: 標準 16×24、中形 8×24、小形 8×12、横倍 32×24、縦倍 16×48、2 倍 32×48、特殊1 16×20、特殊2 20×20、超小形 4×4。標準文字で**横 15 字 × 縦 8 行 = 120 字**、高密度で 496 字。
- 色: レベル A は 4×4 画素の着色単位で 8 色（パターン方式と同じ）+ 半輝度 7 色 + 透明（CMLA 0〜15）。レベル B は 1 画素単位、4,096 色中 16 色（カラーマップ）。
- 漢字は JIS C 6226-1983 の第1水準（受信機内蔵）、第2水準は DJCS（外字として画素で送る）。合計 3,622 字を符号で送る。

### 8 単位符号（別表第十八〜二十号）

- ISO 2022 型。G0〜G3 を GL/GR に呼び出す: LS0 = 00/15、LS1 = 00/14、LS2 = ESC 06/14、LS3 = ESC 06/15、LS1R = ESC 07/14、LS2R = ESC 07/13、LS3R = ESC 07/12、SS2 = 01/9、SS3 = 01/13（ESC = 01/11）。
- 指示: 1 バイト G セット `ESC 02/8..02/11 F`、2 バイト `ESC 02/4 [02/9..02/11] F`、DRCS は `… 02/0 F`。終端符号 F: 漢字系 04/2、英数 04/10、平仮名 03/0、片仮名 03/1、モザイク A〜D 03/2〜03/5、DRCS-0 04/0、DRCS-1〜15 04/1〜04/15、マクロ 07/0。
- C0 制御: NUL、BEL、APB/APF/APD/APU/APR（動作位置移動）、PAPF、APS、CS（画面消去）、CAN 等（別記第10）。
- C1 制御: 前景色 BKF/RDF/GRF/YLF/BLF/MGF/CNF/WHF、COL、POL、SSZ/MSZ/NSZ/SZX、FLC、CDC、MCS/MCT、WMM、TIME（処理待ち・音ステータス待ち・付加音開始）等（別記第11）。CSI 拡張は別記第12。符号値の表は別記第9の画像。

### フォトグラフィック図形（別表第二十三・二十四号）

ハイブリッド方式の中の「画素伝送」。パターン方式の画面はこれで表現できる。

- データユニットデータ = フィールド制御部（9 バイト: 書込みモード、Py/Px、By/Bx、Uy/Ux、走査方向 SD、Fy/Fx）+ ユニットデータ部（ユニット制御 UC1 + 表示機能データ + パターンデータ）。
- ブロックサイズ（標準密度）は縦 4/12/24、横 4/8/16（単位 1/256）。
- ユニット制御 UC1: b2 パターン圧縮、b3 パターン有無、b4 表示機能データ圧縮、b5 コンシール、b6 フラッシング、b7 背景色、b8 前景色。
- 表示機能状態符号（前景・背景色、4 ビット）: 0 黒、1〜7 最大輝度 赤緑黄青マゼンタシアン白、8 透明、9〜15 半輝度。

### 付加音（別表第十七・二十二号）

- 付加音情報データユニット（02/12）のデータは「（音番号）+ 付加音開始 … 付加音終了」を連ねたもの。中身は**メロディ部パート**（0 個以上）、**リズム部パート**（0 個以上）、**制御部パート**（0 または 1）。1 パート = 単音。パートは優先順位の高い順に送り、発音数の少ない受信機は先頭から採る。
- 符号集合: GL = 音高音長符号集合、C1 = 付加音制御符号集合、GR = 音強修飾符号集合（追加機能）。C0 は NUL のみ。
- **音高符号**（GL、7 ビット値 I）: `0x20` = RST（休符）、`0x21` = A0 〜 `0x78` = C8、`0x7F` = IP（リズムパート音発生）。周波数 f = 440 × 2^((I − 81)/12) Hz（A4 = 0x51）。
- **音長符号**（GL）: `0x41`〜`0x7F` = 1〜63 Tu、`0x40` = 64 Tu。音符は必ず「音高 1 バイト + 音長 1 バイト」。
- **単位時間 Tu**: 基本機能 20〜255 ms、追加機能 1〜255 ms。付加音開始（SMC）の第 2 パラメタで指定。
- **制御符号**（C1）: SMC 0x80（付加音開始）、SMP 0x81（メロディ部パート開始）、SRP 0x82（リズム部パート開始）、SCP 0x83（制御部パート開始）、EMC 0x84（付加音終了）、EPT 0x85（パート終了）、LBL 0x88、JMP 0x89、RPT 0x8A、BRA 0x8B、CTM 0x8C（音色再指定）、SLV 0x90（強弱）、LRT 0x98（音長拡大）、TIE 0x9A、MNB 0x9C（音番号）、TEP 0x9F（パラメタ終端）。
- パラメタは 3/0〜3/9 を数字とする 10 進表記で上位桁から並べ、区切り・終端は **3/11**。例: SMC `3/0 3/11` `<Tu の 10 進> 3/11`。
- **音色**（SMP/SRP/CTM の 4 桁選択パラメタ P1 P2 P3 P4、P3・P4 は省略可）。基本機能（＊なし）:

| メロディ | P1 P2 P3 P4 | | リズム | P1 P2 P3 P4 |
|---|---|---|---|---|
| バイオリン | 1 0 0 0 | | スネアドラム | 1 0 0 0 |
| ギター | 1 1 0 0 | | バスドラム | 1 1 0 0 |
| ピアノ | 1 2 0 0 | | トムトム（中） | 2 0 0 0 |
| フルート | 2 0 0 0 | | トップシンバル | 3 0 0 0 |
| クラリネット | 2 1 0 0 | | クローズハイハット | 3 1 0 0 |
| オーボエ | 2 2 0 0 | | | |
| トランペット | 2 3 0 0 | | | |
| パイプオルガン | 3 0 0 0 | | | |
| ビブラフォン | 4 0 0 0 | | | |

  追加機能（レベル B）はメロディ 32 種（チェロ 1002、ストリングス 1080、エレキギター 1101、ハープシコード 1102、ハープ 1103、マンドリン 1104、ピッチカート 1170、電気ピアノ 1201、口笛 2002、サキソフォン 2101、アコーディオン 2103、ホルン 2302、チューバ 2303、ミュートブラス 2370、ブラスアンサンブル 2380、コーラス 3100、グロッケンシュピール 4002、シロフォン 4003、チャイム 4006、ティンパニー 4007、三味線 5100、琴 5103、尺八 6000 など）とリズム 16 種。全表は別表第二十二号の別記第6・第7。
- **同時発音数**: 基本 メロディ 6 + リズム 5、追加 メロディ 16 + リズム 8。
- **強弱 SLV**: 8 = 0 dB、7 = −3 dB … 1 = −21 dB（3 dB 刻み）。追加機能で R8〜R1 = −24〜−45 dB（パラメタ `3/0 3/n`）。
- 繰返し: LBL（0〜255）、JMP、RPT M（M−1 回戻って M 回目に通過）、BRA M（M 回目に分岐）。それぞれ最大 256、ループ内の入れ子総数 64。
- 1 ページの付加音情報データユニットは基本 200 パケット、追加 400 パケットまで。
- 画面との同期: C1 の `TIME 02/1 N2`（音ステータス待ち）、`TIME 02/2 N2`（音番号 N2 の付加音開始）。音ステータス番号は制御部パートの IP ごとに 1 増える。

## パターン方式の扱い

**わかっていること**: 物理層・データライン（296 ビット、CR・FC）はハイブリッドと同一で、サービス識別符号で区別される。画面は 248 × 204 画素、4 × 4 画素単位の 8 色。1983 年の技術基準は「テレビジョン文字多重放送に関する送信の標準方式」（昭和 57 年郵政省令第70号）と無線設備規則。

**わかっていないこと**: パターン方式のデータパケット内の構成（サービス識別符号の値、画面アドレス、ランレングスか直接画素か、誤り訂正が (272,190) 以前の (8,4) 拡大ハミングや水平垂直パリティだったか）。山田論文によると、(272,190) 符号はパターン方式のサービス限界を基準に**後から**評価されたもので、パターン方式自体は別の誤り保護だった可能性が高い。

**方針**:

1. まず「ハイブリッド方式の一層フォトグラフィック図形だけで画面を送るページ」を**パターン方式相当**として実装する（規格が確定しており、受信側の描画も共通化できる）。
2. 1983 年の原フォーマットは資料を入手してから `PatternLegacy` として別に追加する。それまではコード中で `TODO(spec)` とする。

## 付加音の再生 — ymfm による YM2413 (OPLL)

- **ymfm**（Aaron Giles、BSD-3-Clause）は YM2413 / YM2423 / YMF281 / DS1001 (VRC7) をサポート。Rust からは **`ymfm-sys`** クレート（0.2.0、ymfm を build.rs で C++17 ビルド、OPLL の音色 ROM 差し替え API あり）が使える。自前でラップする場合も `cc` クレートで同様にできる。
- YM2413 はデータシートで音色が「テレテキスト・キャプテン対応」とされ、**リズムモードのメロディ 6 音 + リズム 5 音（BD・SD・TOM・TOP-CY・HH）**、**音量 4 ビット 3 dB 刻み（0〜−45 dB）** が付加音の基本機能（6 + 5 音、SLV 8 段階 + R8〜R1 の 16 段階）と一致する。
- 内蔵音色との対応（YM2413 の音色番号は一般に知られた ROM 表による。**MUSCOT との公式対応表は未確認**）:

| MUSCOT（基本） | YM2413 | | MUSCOT（基本） | YM2413 |
|---|---|---|---|---|
| バイオリン | 1 Violin | | トランペット | 7 Trumpet |
| ギター | 2 Guitar | | パイプオルガン | 8 Organ |
| ピアノ | 3 Piano | | ビブラフォン | 12 Vibraphone |
| フルート | 4 Flute | | スネア / バスドラム / トム / トップシンバル / ハイハット | リズム SD / BD / TOM / TOP-CY / HH |
| クラリネット | 5 Clarinet | | | |
| オーボエ | 6 Oboe | | | |

  追加機能の音色のうちホルン（9 Horn）、ハープシコード（11 Harpsichord）、エレキギター（15 Electric Guitar）は内蔵音色がある。それ以外は最も近い音色か、ユーザー音色（音色 0）に割り当てる。メロディ 16 音のレベル B は YM2413 1 個では足りないので、複数インスタンスにするか、優先順位の低いパートを落とす（規格上も許される）。
- 周波数: OPLL のサンプルレートは 3.579545 MHz / 72 ≈ 49,716 Hz。F-number 9 ビット・ブロック 3 ビットで A0（27.5 Hz）〜C8（4,186 Hz）の 88 音をすべて表せる。
- 置き場所: 付加音は**受信機が鳴らす音**なので、`decoder` 側（キャプションと同じ位置）でページを解釈し、OPLL の出力を `audio` の出力に重ねる。リアルタイム経路ではフレームごとに Tu 刻みでシーケンサを進め、ymfm を音声サンプルレートにリサンプルする。

## 実装ステップ

**進捗**: 1・2 は独立クレート `crates/jtes`（vhs-core に依存しない）として実装済み。物理層は省令第77号（別図第三号の 50 % 点の定義、使用ラインの対）に合わせてある。`vbi.rs` は `VbiParams::teletext_system = Jtes` のとき、送出第1モードの空パケット（全 NUL、CI 巡回）を送る。データグループ層ができたら `vbi::jtes_packet` を差し替える。

1. **データライン層**: `jtes` モジュールを新設。サービス識別、CI・フラグ、(272,190) 符号器（LFSR）、296 ビット → 波形（ロールオフ 0.6）。テスト: 符号語が G(X) で割り切れる、送出ビット順、波形の開始位置と振幅。
2. **多数決論理復号器**: 受信側とテスト用。(273,191) 差集合巡回符号の直交チェック和で 8 ビット訂正。テスト: ランダムに ≤ 8 ビット反転して必ず復元。
3. **データグループ・番組データ**: SOH/STX/ETB/ETX/EOT、データグループヘッダ、CRC-16、データヘッダ（番組・ページ・索引）、データユニット、データブロックへの分割と NUL 詰め。送出スケジューラ（ライン対・送出モード・ページ間隔・索引 20 秒）。
4. **8 単位符号の本文**: UTF-8 → JIS（JIS C 6226-1983）、英数・ひらがな・カタカナ集合の切替、色・大きさ・位置の C0/C1 制御。入力は既存の `caption_text` と同様の簡易マークアップにする。
5. **フォトグラフィック（パターン相当）**: 画像 → 248 × 204 の 2 値 + 4 × 4 着色 → MH 符号。DRCS・DJCS（外字）。
6. **付加音の符号器**: MML 風テキスト（音色・テンポ・音符・強弱・リピート）→ 別表第二十二号の符号列。
7. **受信側**: スライサ → 復号 → データグループ再構成（CRC 検査）→ 番組選択 → 8 単位符号の解釈 → 画面描画（スーパー表示・多画面）→ MUSCOT シーケンサ → ymfm OPLL。
8. （任意）ジオメトリック図形（別表第二十一号、レベル B）、多層フォトグラフィック、パターン方式の原フォーマット。
